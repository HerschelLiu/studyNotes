## 1. 适用场景

VitePress 适合：

- Markdown 技术文档、组件库文档；
- 需要 Vue 交互示例、源码查看；
- 希望构建产物是纯静态文件，直接托管 GitHub Pages。

前置：Node.js 18+，npm。

## 2. 初始化

```bash
mkdir my-docs
cd my-docs
npm init -y
npm install -D vitepress vue
npx vitepress init
```

手工创建也可以，目录如下：

```text
my-docs/
├── .vitepress/
│   ├── config.mts
│   └── theme/
│       └── index.ts
├── index.md
├── guide/
│   └── getting-started.md
└── package.json
```

`package.json`：

```json
{
  "name": "my-docs",
  "private": true,
  "type": "module",
  "scripts": {
    "dev": "vitepress dev",
    "build": "vitepress build",
    "preview": "vitepress preview"
  },
  "devDependencies": {
    "vitepress": "^1.6.4",
    "vue": "^3.5.0"
  }
}
```

## 3. 最小配置

`.vitepress/config.mts`：

```ts
import { defineConfig } from 'vitepress'

export default defineConfig({
  lang: 'zh-CN',
  title: '我的文档',
  description: '我的技术文档',
  base: process.env.DOCS_BASE || '/',
  cleanUrls: false,
  markdown: {
    theme: { light: 'github-light', dark: 'github-dark' },
  },
  themeConfig: {
    nav: [
      { text: '首页', link: '/' },
      { text: '指南', link: '/guide/getting-started' },
    ],
    sidebar: {
      '/guide/': [
        {
          text: '指南',
          items: [
            { text: '快速开始', link: '/guide/getting-started' },
          ],
        },
      ],
    },
    outline: { level: [2, 3], label: '本页目录' },
    search: { provider: 'local' },
    editLink: {
      pattern: 'https://github.com/<user>/<repo>/edit/main/:path',
      text: '在 GitHub 上编辑此页',
    },
  },
})
```

`base` 是部署子路径的关键：

- 用户/组织根站点：`/`
- 项目站点 `https://<user>.github.io/<repo>/`：`/<repo>/`
- 自定义域名：`/`

## 4. 首页

`index.md`：

```md
---
layout: home

hero:
  name: 我的文档
  text: 把知识变成可检索的页面
  tagline: Markdown 写作，静态发布
  actions:
    - theme: brand
      text: 开始阅读
      link: /guide/getting-started

features:
  - icon: 📘
    title: 指南
    details: 从安装到部署
    link: /guide/getting-started
---
```

`layout: home` 只影响首页；其他页面是普通文档布局。

## 5. 写文档

每篇文档：

```md
---
title: "快速开始"
---

## 安装

正文从二级标题开始。
```

约定：

- `title` 用于侧边栏、浏览器标题和 SEO；
- 正文不再写一级标题，避免和主题标题重复；
- 站内链接用相对 `.md`：

```md
[写作规范](./writing.md)
[Frontmatter](../reference/frontmatter.md)
```

VitePress 构建时会把 `.md` 链接转换成路由。

图片放在 Markdown 同目录或 `public/`：

```md
![截图](./images/demo.png)
```

## 5.1 public 目录与 logo

VitePress 的公共资源目录是：

```text
<srcDir>/public/
```

默认 `srcDir` 是项目根目录，所以是 `public/logo.svg`。

如果修改了 `srcDir`，public 目录也会跟着移动。例如 `srcDir` 指向仓库根 `content/` 时，必须把 logo 放到：

```text
content/public/logo.svg
```

而不是 `apps/vitepress/public/logo.svg`。否则开发服务器会返回 HTML fallback，浏览器里就是破图。

配置：

```ts
export default defineConfig({
  head: [
    ['link', { rel: 'icon', type: 'image/svg+xml', href: `${base}logo.svg` }],
  ],
  themeConfig: {
    logo: '/logo.svg',
  },
})
```

访问路径：

```text
开发：/logo.svg
GitHub Pages：/studyNotes/vitepress/logo.svg
```

## 6. 侧边栏

手写：

```ts
sidebar: {
  '/guide/': [
    {
      text: '指南',
      items: [
        { text: '快速开始', link: '/guide/getting-started' },
        { text: '写作规范', link: '/guide/writing' },
      ],
    },
  ],
}
```

目录大时，可以用脚本在配置加载时扫描 Markdown 生成 sidebar，避免手写几百条。扫描范围就是 `srcDir`，默认是项目根目录。

## 7. 自定义主题

`.vitepress/theme/index.ts`：

```ts
import DefaultTheme from 'vitepress/theme'
import './custom.css'

export default {
  extends: DefaultTheme,
}
```

`custom.css` 可覆盖品牌色、布局宽度、代码块样式。

## 8. Vue 交互示例

注册组件：

```ts
import DefaultTheme from 'vitepress/theme'
import DemoBlock from './components/DemoBlock.vue'
import './custom.css'

export default {
  extends: DefaultTheme,
  enhanceApp({ app }) {
    app.component('DemoBlock', DemoBlock)
  },
}
```

Markdown 中使用：

```md
<DemoBlock src="counter">
```

组件内部用 `import.meta.glob('../demos/**/*.vue', { query: '?raw' })` 读取源码，实现「运行 + 查看源码」。

如果不需要交互，可完全不写自定义主题。

## 9. 本地与构建

```bash
npm run dev        # http://localhost:5173/
npm run build      # .vitepress/dist
npm run preview    # 预览生产构建
```

模拟 GitHub Pages 子路径：

```bash
DOCS_BASE=/my-repo/ npm run build
DOCS_BASE=/my-repo/ npm run preview
```

## 10. 部署到 GitHub Pages

单站 workflow：

```yaml
name: Deploy VitePress

on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: pages
  cancel-in-progress: false

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: npm
      - run: npm ci
      - run: npm run build
        env:
          DOCS_BASE: /<repo>/
      - run: touch .vitepress/dist/.nojekyll
      - uses: actions/configure-pages@v5
      - uses: actions/upload-pages-artifact@v3
        with:
          path: .vitepress/dist

  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - id: deployment
        uses: actions/deploy-pages@v4
```

然后在仓库 **Settings → Pages → Source** 选择 **GitHub Actions**。

## 11. 类型检查

VitePress 运行不依赖 TS，但 `config.mts` 用了 `process.env`，建议加一份 tsconfig，编辑器才能正常提示：

```json
{
  "compilerOptions": {
    "target": "ESNext",
    "module": "ESNext",
    "moduleResolution": "Bundler",
    "strict": true,
    "noEmit": true,
    "skipLibCheck": true,
    "allowJs": true,
    "checkJs": false,
    "types": ["node", "vite/client"]
  },
  "include": [
    "./*.mts",
    "./env.d.ts",
    "./plugins/**/*.ts",
    "./sidebar.mjs",
    "./theme/**/*.ts",
    "./theme/**/*.vue",
    "./demos/**/*.vue"
  ]
}
```

```bash
npm install -D @types/node
npx tsc -p .vitepress
```

`env.d.ts` 用于给 `*.vue` 导入补类型：

```ts
declare module '*.vue' {
  import type { DefineComponent } from 'vue'
  const component: DefineComponent<Record<string, unknown>, Record<string, unknown>, unknown>
  export default component
}
```

常见 TS 报错：

| 报错 | 原因 | 处理 |
| --- | --- | --- |
| `Cannot find name 'process'` | 缺 Node 类型 | 安装 `@types/node`，tsconfig 加 `"types": ["node"]` |
| `Cannot find module '*.vue'` | 缺 Vue 模块声明 | 添加 `env.d.ts` |
| `Property 'glob' does not exist on type 'ImportMeta'` | 自定义 `types` 后没包含 Vite 的类型 | tsconfig 写 `"types": ["node", "vite/client"]` |
| `Type 'Plugin' is not assignable to type 'PluginOption'` | 存在两套 Vite：根目录的 Vite 与 vitepress 内置的 Vite 版本不同（monorepo 中 Astro 会装 Vite 8） | 在 VitePress 应用内安装与 vitepress 一致的 `vite@^5.4.14`，重新安装后重启 TS 服务 |
| `sidebar: generateSidebar()` 类型不匹配 | JS 文件返回值被推断成 `any` | 给函数加 JSDoc，例如 `@returns {import('vitepress').DefaultTheme.SidebarMulti}` |

## 12. 常见问题

| 现象            | 处理                                             |
| --------------- | ------------------------------------------------ |
| 页面 404        | 检查 `base` 是否以 `/` 开头结尾，链接是否带 base |
| 侧边栏空        | `sidebar` 路径和文档路径不一致                   |
| 首页样式不对    | 首页 frontmatter 需要 `layout: home`             |
| 中文标题重复    | 正文不要再写 H1，交给主题                        |
| 构建报 Vue 插值 | Markdown 中的 `{{ }}` 需要转义或放到代码块       |

GitHub Pages 的 base、自定义域名与排错详见
[GitHub Pages 静态站点部署指南](</代码/系统与运维/github-pages/GitHub Pages 静态站点部署指南.md>)。
