> 面向已经会写前端、用过 npm，但没系统学过 Node 的人。
>
> 目标不是背 API，而是能独立写出、测试、部署一个 Node 服务，并看懂仓库里的脚本。

## 1. 先明确学到什么程度

| 层次 | 能力 | 对应内容 |
| --- | --- | --- |
| 会用 | 跑脚本、装依赖、看懂报错 | npm、`package.json`、`node` 命令 |
| 会写 | 写 CLI、静态服务器、接口 | `fs`、`http`、Stream、`child_process` |
| 能上线 | 有测试、日志、容器、部署 | 工程化与交付 |
| 能排障 | 会看事件循环、内存、性能 | 运行时与可观测性 |

前端日常接触的 npm、Vite 插件、脚手架只是最表层的 Node。真正拉开差距的是：**异步模型、流、进程、以及把服务跑稳的能力**。

## 3. 四个阶段与产出

### 阶段一：运行时

读：[事件循环与异步](./基础/事件循环与异步.md)、[Stream、Buffer 与文件](./基础/Stream、Buffer与文件.md)

产出：

- 一个批量处理文件的 CLI（重命名、按类型归档、统计行数）；
- 能解释 `setTimeout`、`Promise.then`、`await` 的输出顺序；
- 能用 `pipeline` 处理大文件而不爆内存。

### 阶段二：HTTP 与后端

读：[HTTP 与 REST](./后端/HTTP与REST.md)、[数据库、鉴权与安全](./后端/数据库、鉴权与安全.md)、[Express 项目规范](./后端/Express项目规范.md)

产出：

- 一个带注册登录、CRUD、分页、统一错误格式的 API；
- 会用参数校验、连接池、事务；
- 能说清 Session 与 JWT 的取舍；
- 能按目录规范拆分 route / controller / service / repository，并补上接口测试。

### 阶段三：工程化与上线

读：[测试、日志与部署](./工程化/测试、日志与部署.md)

产出：

- API 有单元测试和接口测试；
- 有结构化日志、优雅退出、健康检查；
- 用 Docker 跑起来，部署到一台服务器并配好 HTTPS。

### 阶段四：进阶与方向

读：[NestJS 企业级实践](./后端/NestJS企业级实践.md)、[练手项目](./实战/练手项目.md)

产出：

- 实时能力（WebSocket / SSE）；
- 队列与缓存（Redis、BullMQ）；
- 性能压测与排查（autocannon、`--inspect`）；
- 选定一个方向深入：NestJS、CLI、BFF、桌面端或基础设施。

> 想确认“学的这些企业里到底用不用”，看[后端技能地图与岗位对照](./后端/后端技能地图与岗位对照.md)：里面区分了 Node 专属能力和可迁移的通用后端能力。

## 4. 环境准备

```bash
# 推荐用 nvm 管理版本
node -v    # 20 或 22 LTS
npm -v
```

仓库已经使用 Node 22 构建，本地用 20/22 都可以。装依赖统一在仓库根目录执行：

```bash
npm install
```

## 5. 怎么学才有效

1. **每个概念都要有一个能跑的文件**：不要只看文章，至少写 20 行验证；
2. **先写再抽象**：先用 `http` 手写路由，再换 Express/Fastify，才知道框架替你做了什么；
3. **用真实脚本练手**：仓库里的 `scripts/pages.mjs` 就是很好的素材，已拆成一篇笔记：
   - [构建编排与子进程](./工程化/pages脚本拆解-构建编排与子进程.md)
4. **每篇笔记按四段写**：为什么需要 → 最小示例 → 常见坑 → 项目里怎么用。
