title: "进程、线程与子进程"
---

> 前置：能写简单脚本，知道 `package.json` 的 scripts。
>
> 目标：会启动外部命令、处理退出码、在 CPU 密集任务时不阻塞主线程。

## 1. 三个概念

| 概念 | 说明 | Node 中的对应 |
| --- | --- | --- |
| 进程 | 独立的运行实例，有独立内存 | 每次 `node xxx.js` 就是一个进程 |
| 线程 | 进程内的执行单元，共享内存 | 主线程 + libuv 线程池 + `worker_threads` |
| 子进程 | 由当前进程启动的另一个进程 | `child_process` |

JavaScript 代码默认只在**主线程**执行。文件读写、DNS 等由 libuv 线程池完成，但 JavaScript 回调仍回到主线程。

## 2. process：当前进程信息

```js
console.log(process.argv)        // [node路径, 脚本路径, ...参数]
console.log(process.env.NODE_ENV)
console.log(process.pid)
console.log(process.cwd())

process.exitCode = 1             // 推荐：让进程自然结束，退出码为 1
// process.exit(1)               // 立即退出，可能丢日志、丢未完成写入
```

信号处理是服务优雅退出的基础：

```js
process.on('SIGTERM', () => {
  console.log('收到 SIGTERM，准备退出')
  server.close(() => {
    process.exit(0)
  })
})
```

## 3. 启动子进程的四种方式

```js
import { exec, execFile, spawn, fork } from 'node:child_process'
```

| API | 是否走 shell | 适用 |
| --- | --- | --- |
| `exec` | 是 | 简单命令、输出较小 |
| `execFile` | 否 | 直接执行可执行文件，参数更安全 |
| `spawn` | 否（可配置） | 长时间任务、大输出、流式处理 |
| `fork` | 否 | 启动另一个 Node 模块，并建立 IPC |

最小示例（同步等待）：

```js
import { spawnSync } from 'node:child_process'

const result = spawnSync('npm', ['run', 'build'], {
  stdio: 'inherit',
  shell: process.platform === 'win32',
})

if (result.status !== 0) {
  console.error('构建失败')
  process.exit(1)
}
```

异步版本：

```js
import { spawn } from 'node:child_process'

const child = spawn('node', ['worker.js'], { stdio: 'inherit' })

child.on('error', (error) => console.error('启动失败', error))
child.on('exit', (code, signal) => {
  console.log(`退出码 ${code}，信号 ${signal}`)
})
```

要点：

- `stdio: 'inherit'` 让输出直接打印到终端；默认是管道，需要自己消费；
- `exit` 事件只表示进程退出，不保证所有输出已读完；需要完整输出时监听 `close`；
- 拿到 `child` 后可以 `child.kill('SIGTERM')` 终止。

## 4. 安全：不要把用户输入拼进 shell

```js
// 危险：用户传入 "a; rm -rf /" 就会被执行
exec(`git log ${userInput}`)

// 安全：参数分离，不经过 shell
execFile('git', ['log', userInput])
```

`exec` 会把整条字符串交给 shell 解析；只要参数来自外部，就可能被注入。

## 5. CPU 密集任务：worker_threads

```js
// main.js
import { Worker } from 'node:worker_threads'

const worker = new Worker(new URL('./hash-worker.js', import.meta.url), {
  workerData: { file: 'big.bin' },
})

worker.on('message', (result) => console.log('结果', result))
worker.on('error', (error) => console.error(error))
worker.on('exit', (code) => console.log('worker 退出', code))
```

```js
// hash-worker.js
import { parentPort, workerData } from 'node:worker_threads'
import { createHash } from 'node:crypto'
import fs from 'node:fs'

const hash = createHash('sha256')
hash.update(fs.readFileSync(workerData.file))
parentPort.postMessage(hash.digest('hex'))
```

适合放进 worker 的任务：压缩、加密、图片处理、大 JSON 解析、复杂计算。I/O 密集任务不需要 worker。

## 6. 多进程与 cluster

- 单机多核压满 CPU：可以用 `cluster` 或进程管理器（PM2）起多个实例；
- 多实例之间不共享内存，会话要放 Redis 之类的共享存储；
- 现代部署更常见的是**多容器 + 负载均衡**，不一定用 `cluster`。

## 7. 优雅退出

```js
const server = app.listen(3000)
let shuttingDown = false

async function shutdown(signal) {
  if (shuttingDown) return
  shuttingDown = true
  console.log(`收到 ${signal}，停止接收新请求`)

  server.close(async () => {
    await db.end()
    process.exit(0)
  })

  setTimeout(() => process.exit(1), 10_000).unref()
}

process.on('SIGTERM', () => shutdown('SIGTERM'))
process.on('SIGINT', () => shutdown('SIGINT'))
```

关键点：停止接收新请求、等待进行中的任务、释放连接、设置兜底超时。

## 8. 常见坑

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 子进程输出看不到 | 默认 `stdio` 是管道 | 用 `stdio: 'inherit'` 或自己读流 |
| Windows 启动 npm 报错 | `.cmd` 不能直接 spawn | 配合 `shell: true` |
| 命令注入 | `exec` 拼接用户输入 | 用 `execFile` / 参数数组 |
| 子进程不退，父进程也不退 | 子进程仍存活 | 记录 `child`，退出时 `kill` |
| 服务重启时请求被中断 | 没处理 `SIGTERM` | 实现优雅退出 |
| 计算任务把接口卡住 | 主线程做 CPU 密集计算 | 移到 `worker_threads` |
| 调用 `process.exit` 丢日志 | 立即终止 | 用 `process.exitCode` + 自然退出 |

## 9. 项目里怎么用

- 构建脚本：`spawnSync` 依次执行两个 SSG 构建，检查退出码（见[构建编排与子进程](../工程化/pages脚本拆解-构建编排与子进程.md)）；
- 开发服务器编排：`spawn` + `Promise.all` 并行启动；
- 部署脚本：`execFile('docker', [...])`，避免 shell 拼接；
- 服务进程：监听 `SIGTERM`，配合 Docker / systemd 平滑重启。

## 10. 练习

1. 写一个脚本，依次执行 `node -v` 和 `npm -v`，任一失败则退出码为 1；
2. 用 `spawn` 启动一个长时间运行的命令，30 秒后发送 `SIGTERM`；
3. 把一个大数分解任务放进 `worker_threads`，对比主线程执行的耗时；
4. 给一个 Express/Fastify 服务加上优雅退出，验证 `Ctrl+C` 时正在处理的请求能完成。
