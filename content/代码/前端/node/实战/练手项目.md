## 项目一：文件整理 CLI

**练什么**：`fs`、`path`、Stream、`process.argv`、错误处理。

需求：

- 扫描指定目录，按扩展名归类到 `images/`、`docs/`、`videos/` 等子目录；
- 支持 `--dry-run` 只打印计划，不真正移动；
- 支持 `--log` 把操作记录写入文件；
- 遇到重名自动追加序号；
- 统计处理数量与耗时。

技术点：

```js
const args = process.argv.slice(2)
const dryRun = args.includes('--dry-run')
const target = args.find((arg) => !arg.startsWith('--'))
```

验收：

- [ ] 1000 个测试文件能在合理时间内处理完
- [ ] `--dry-run` 不修改磁盘
- [ ] 重名文件不覆盖
- [ ] 失败文件被记录并继续处理其他文件

扩展：加配置文件、并发处理、撤销上一次操作。

## 项目二：TODO REST API

**练什么**：HTTP、REST、数据库、鉴权、测试、Docker。

功能：

- 注册 / 登录 / 退出；
- 每个用户只能看到自己的 TODO；
- 增删改查、分页、按完成状态过滤；
- 统一错误格式与参数校验；
- 登录接口限流。

建议技术栈：

```text
Fastify + PostgreSQL + pg/Kysely + zod + argon2 + node:test
```

接口示例：

```text
POST   /api/auth/register
POST   /api/auth/login
GET    /api/todos?page=1&pageSize=20&done=false
POST   /api/todos
PATCH  /api/todos/:id
DELETE /api/todos/:id
```

验收：

- [ ] 未登录访问返回 401
- [ ] 修改别人的 TODO 返回 403/404
- [ ] 参数错误返回 422 且不写库
- [ ] 有接口测试，CI 能跑
- [ ] Docker 一条命令启动

扩展：软删除、标签、分享链接、操作日志。

## 项目三：实时任务队列

**练什么**：WebSocket / SSE、Redis、队列、并发控制、可观测性。

需求：

- 提交一个耗时任务（例如生成报表），立即返回任务 id；
- 后台 worker 消费队列执行；
- 前端通过 WebSocket 或 SSE 接收进度；
- 任务状态可查询，失败可重试；
- 限制并发数，避免打满 CPU。

建议技术栈：

```text
Fastify + BullMQ + Redis + WebSocket(ws) 或 SSE
```

关键结构：

```text
API 进程：接收请求 → 入队 → 返回 jobId
Worker 进程：取任务 → 更新进度 → 写结果
推送层：按 jobId 订阅进度，转发给浏览器
```

验收：

- [ ] 服务重启后队列任务不丢
- [ ] 并发数可配置
- [ ] 失败任务有重试次数与最终状态
- [ ] 能看到每个任务的耗时和失败原因

扩展：优先级队列、定时任务、任务取消、进度持久化。

## 项目四：NestJS 企业级模块

**练什么**：模块化、依赖注入、DTO、Guard、拦截器、OpenAPI、测试。

选一个真实业务模块（例如「通知中心」或「审计日志」），用 NestJS 实现：

- 独立的 domain module，包含 controller / service / dto / repository；
- 全局 `ValidationPipe` + 统一异常过滤器 + 响应拦截器；
- JWT 登录 + 角色 Guard + 资源归属校验；
- 通过 service 调用另一个模块，不允许跨模块直接访问 repository；
- Swagger 文档、健康检查、结构化日志；
- 单元测试 + e2e 测试；
- Docker 部署并验证优雅退出。

验收：

- [ ] 模块边界清晰，无循环依赖
- [ ] 参数、权限、错误格式三处统一
- [ ] `/docs` 能直接联调
- [ ] `npm run test` 与 e2e 均通过
- [ ] 能用一段话说明为什么选 Nest 而不是 Express

## 验收评分表（与岗位对齐）

每个项目按 1–5 分自评，3 分达到“可交付”，4 分以上达到“可独立负责模块”。

| 维度 | 1 分 | 3 分 | 5 分 |
| --- | --- | --- | --- |
| 功能完整度 | 主流程能跑 | 边界与异常齐全 | 幂等、重试、并发都考虑 |
| API 设计 | 能用 | REST 规范、错误结构统一 | 版本化、契约文档、兼容性 |
| 数据建模 | 单表 CRUD | 索引、外键、事务 | 迁移、慢查询优化、容量评估 |
| 安全 | 有登录 | 鉴权 + 参数校验 + 限流 | 越权、CSRF、审计、脱敏 |
| 测试 | 手工验证 | 关键接口测试 | 分层测试、覆盖率、CI |
| 可运维性 | 本地能跑 | 日志、健康检查、Docker | 监控告警、发布回滚、故障演练 |
| 代码质量 | 能读懂 | 分层清晰、命名一致 | 可扩展、低耦合、有文档 |
| 协作 | 无文档 | README + 接口说明 | 需求拆解、评审、复盘 |

### 岗位考核点

| 目标岗位 | 必须达到 |
| --- | --- |
| 初级后端 | 项目一 + 项目二，评分 ≥3 |
| 中级后端 | 项目二 + 项目三，评分 ≥4，能讲清一次线上问题排查 |
| 中高级 / 架构方向 | 项目四 + 系统设计题，评分 ≥4，能主导模块设计 |

### 系统设计加练（中高级）

选一个真实场景，例如「订单创建」：

- 如何防止重复下单（幂等键 + 唯一索引）；
- 扣库存与创建订单如何保证一致性（本地事务 / 消息最终一致 / outbox）；
- 第三方支付回调重复、乱序怎么处理；
- 峰值流量下如何限流、降级、排队；
- 如何做容量评估与监控指标设计。

输出一页设计文档：目标、约束、方案对比、失败场景、监控与回滚。

## 建议节奏

| 周 | 内容 | 产出 |
| --- | --- | --- |
| 1 | 事件循环、Stream、进程 | 文件整理 CLI |
| 2 | HTTP 与 REST、Express 规范 | 手写 TODO API + Express 分层版本 |
| 3 | 数据库与鉴权 | 登录 + 权限 + 测试 |
| 4 | 工程化 | 日志、Docker、部署 |
| 5 | NestJS | 企业级模块（项目四） |
| 6 | 实时与队列 | 任务队列项目 |
| 7 | 性能与排障 | 压测报告、优化记录 |

不必严格按周，关键是**每个阶段都有可运行的产物**。

## 自测清单

- [ ] 能解释 `setTimeout`、`Promise`、`await` 的执行顺序
- [ ] 能处理 1GB 文件而不爆内存
- [ ] 能不用框架写出可用的 HTTP 接口
- [ ] 能设计表结构并写事务
- [ ] 能实现安全的登录与权限校验
- [ ] 能写单元测试和接口测试
- [ ] 能用 Docker 部署并用 Nginx 配 HTTPS
- [ ] 能定位一次接口变慢的原因

## 记录方式

每个项目写一篇复盘，固定四段：

1. 需求与设计；
2. 关键代码与取舍；
3. 遇到的问题与解决过程；
4. 如果重做会怎么改。

这样比收藏十篇文章更有用。
