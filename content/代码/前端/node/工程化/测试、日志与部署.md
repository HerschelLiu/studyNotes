> 前置：能写一个可运行的 API，理解环境变量。
>
> 目标：让服务从“本机能跑”变成“别人也能用、出问题能查”。

## 1. 配置：环境变量要有校验

```js
const required = ['DATABASE_URL', 'SESSION_SECRET']

for (const key of required) {
  if (!process.env[key]) {
    throw new Error(`缺少环境变量 ${key}`)
  }
}
```

- 本地用 `.env`（不提交），CI / 服务器用平台的环境变量；
- 启动时校验，缺配置直接失败，比运行到一半报错好；
- 区分 `NODE_ENV=development|production`，但不要用它替代显式配置。

## 2. 日志：结构化，而不是到处 console.log

```js
import pino from 'pino'

export const logger = pino({
  level: process.env.LOG_LEVEL || 'info',
})

logger.info({ userId, todoId }, 'todo created')
```

要点：

- 输出 JSON，方便采集和检索；
- 带上请求 id、用户 id 等上下文；
- 开发环境可以用 `pino-pretty` 美化，生产不要；
- **不要记录**密码、token、完整身份证/手机号。

请求日志：

```js
app.addHook('onRequest', async (request) => {
  request.log.info({ url: request.url, method: request.method }, 'request')
})
```

## 3. 错误处理分层

| 类型 | 例子 | 处理 |
| --- | --- | --- |
| 预期错误 | 参数不合法、未登录、资源不存在 | 返回 4xx，不打印堆栈 |
| 非预期错误 | 空指针、数据库连接断开 | 记录 error 日志，返回 500 |

```js
app.setErrorHandler((error, request, reply) => {
  request.log.error({ err: error }, 'unhandled error')
  const status = error.statusCode || 500
  reply.code(status).send({
    message: status === 500 ? '服务器内部错误' : error.message,
  })
})
```

生产环境不要把堆栈返回给客户端。

## 4. 测试

### 4.1 单元测试

```js
import test from 'node:test'
import assert from 'node:assert/strict'
import { calcTotal } from '../src/price.js'

test('calcTotal 计算总价', () => {
  assert.equal(calcTotal([{ price: 10, count: 2 }]), 20)
})
```

```bash
node --test
```

### 4.2 接口测试

```js
import test from 'node:test'
import assert from 'node:assert/strict'
import { buildApp } from '../src/app.js'

test('创建 todo', async () => {
  const app = buildApp()
  const response = await app.inject({
    method: 'POST',
    url: '/api/todos',
    payload: { title: '写测试' },
  })

  assert.equal(response.statusCode, 201)
  assert.equal(response.json().title, '写测试')
})
```

- 测试用独立数据库或事务回滚，别污染开发数据；
- 至少覆盖：成功、参数错误、未登录、无权限、资源不存在；
- 测试文件按模块命名：`todo.test.js`。

## 5. Docker

```dockerfile
FROM node:22-alpine AS deps
WORKDIR /app
COPY package*.json ./
RUN npm ci

FROM node:22-alpine AS runner
WORKDIR /app
ENV NODE_ENV=production
COPY --from=deps /app/node_modules ./node_modules
COPY . .
EXPOSE 3000
USER node
CMD ["node", "src/server.js"]
```

要点：

- 多阶段构建，运行镜像不带开发依赖；
- 用 `npm ci` 保证锁文件一致；
- 不要以 root 运行；
- `.dockerignore` 排除 `node_modules`、`.git`、日志。

```bash
docker build -t my-api .
docker run --env-file .env -p 3000:3000 my-api
```

## 6. 部署形态

```text
用户 → Nginx（HTTPS、静态资源、反向代理） → Node 进程（3000）
                                             → PostgreSQL / Redis
```

- Nginx 负责 TLS、gzip、超时、限流；
- Node 进程用 systemd、PM2 或容器编排管理；
- 数据库不要暴露公网；
- 配置健康检查：

```js
app.get('/healthz', async () => ({ ok: true }))
```

健康检查只做轻量判断（进程存活、连接可用），不要执行重查询。

## 8. 常见坑

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 容器里找不到模块 | 只复制了 `package.json` 没装依赖 | 多阶段构建 + `npm ci` |
| 本地能连数据库，容器不行 | `localhost` 指向容器自身 | 用服务名或外网地址 |
| 重启时 502 | 进程立刻退出，没有优雅关闭 | 处理 `SIGTERM`，等连接释放 |
| 日志太多磁盘爆 | 没有轮转/采集 | 平台采集或 logrotate |
| 测试互相污染 | 共用同一个数据库 | 独立测试库 + 事务回滚 |
| 时区错乱 | 容器默认 UTC | 统一存 UTC，展示时转换 |

2. 写一个测试：未登录访问受保护接口应返回 401；
