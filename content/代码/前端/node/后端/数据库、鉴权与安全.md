> 前置：完成[HTTP 与 REST](./HTTP与REST.md)，能写增删改查接口。
>
> 目标：把数据存起来，把用户认证做对，避免常见安全漏洞。

## 1. 选型与连接

| 类型 | 场景 | 常见选择 |
| --- | --- | --- |
| 关系型 | 业务数据、事务、复杂查询 | PostgreSQL、MySQL |
| 文档型 | 结构不固定、快速迭代 | MongoDB |
| 缓存 / 队列 | 热点数据、会话、任务 | Redis |

Node 里通过驱动或 ORM 访问数据库：

- 驱动：`pg`、`mysql2`；
- 查询构建器：Kysely；
- ORM：Prisma、Drizzle、TypeORM。

无论用哪种，**连接池**是必须的。不要每个请求 `new Client()`：

```js
import pg from 'pg'

export const pool = new pg.Pool({
  connectionString: process.env.DATABASE_URL,
  max: 10,
  idleTimeoutMillis: 30_000,
})
```

## 2. 参数化查询

```js
// 错误：字符串拼接，SQL 注入
const sql = `select * from users where email = '${email}'`

// 正确：参数化
const { rows } = await pool.query(
  'select id, email from users where email = $1',
  [email],
)
```

原则：**SQL 只写占位符，值永远通过参数数组传入**。表名、排序字段这类不能参数化的部分，要用白名单映射。

## 3. 事务

转账、扣库存这类操作必须在一个事务里：

```js
const client = await pool.connect()
try {
  await client.query('begin')
  await client.query('update accounts set balance = balance - $1 where id = $2', [amount, from])
  await client.query('update accounts set balance = balance + $1 where id = $2', [amount, to])
  await client.query('commit')
} catch (error) {
  await client.query('rollback')
  throw error
} finally {
  client.release()
}
```

要点：

- 从池里 `connect` 拿到的客户端必须 `release`；
- `commit` / `rollback` 都可能失败，错误要向上抛；
- 事务里不要做慢请求（调用第三方接口），会长时间占连接。

## 4. 密码存储

永远不要明文存密码，也不要用 MD5/SHA1。

```js
import argon2 from 'argon2'

const hash = await argon2.hash(password)
const ok = await argon2.verify(hash, inputPassword)
```

- 每个用户独立盐值（库内部处理）；
- 哈希是单向的，不能“解密找回密码”，只能重置；
- 登录失败提示统一为“邮箱或密码错误”，不要泄露账号是否存在。

## 5. Session 还是 JWT

| 维度 | Session | JWT |
| --- | --- | --- |
| 存储 | 服务端（内存/Redis） | 客户端持有 token |
| 撤销 | 删会话即可 | 需要黑名单或短过期 |
| 扩展 | 多实例需共享存储 | 天然无状态 |
| 适用 | 传统 Web、同域 | API、移动端、跨服务 |

Web 场景更推荐 **HttpOnly Cookie + Session**，或 **HttpOnly Cookie 存 refresh token**：

```js
res.setHeader('Set-Cookie', [
  `sid=${sessionId}; HttpOnly; Secure; SameSite=Lax; Path=/; Max-Age=604800`,
])
```

- `HttpOnly`：JS 读不到，降低 XSS 窃取风险；
- `Secure`：只走 HTTPS；
- `SameSite=Lax/Strict`：降低 CSRF 风险；
- 不要把 token 放 `localStorage`。

## 6. 权限控制

认证回答“你是谁”，授权回答“你能做什么”。

```js
const requireRole = (role) => async (request, reply) => {
  if (request.user?.role !== role) {
    return reply.code(403).send({ message: 'Forbidden' })
  }
}
```

- 资源级权限要校验归属：`todo.userId === currentUser.id`；
- 不要只在前端隐藏按钮，后端必须再校验；
- 管理接口和普通接口分开前缀，便于统一加守卫。

## 7. 安全检查清单

| 风险 | 防护 |
| --- | --- |
| SQL 注入 | 参数化查询、白名单排序字段 |
| XSS | 输出转义、CSP、不信任用户 HTML |
| CSRF | SameSite Cookie、CSRF token |
| 暴力登录 | 限流、失败次数锁定、验证码 |
| 越权 | 每个资源校验归属与角色 |
| 敏感信息泄露 | 错误信息不返回堆栈、日志脱敏 |
| 密钥硬编码 | 环境变量 / 密钥管理，不进仓库 |
| 依赖漏洞 | 定期 `npm audit`，锁定版本 |
| 请求体过大 | 限制大小、限制上传类型 |
| 未配置安全头 | `helmet` 或反向代理统一加 |

## 8. 常见坑

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 连接数暴涨 | 每请求新建连接 | 使用连接池并复用 |
| 事务没生效 | 用了池的 `query` 而不是事务客户端 | 所有语句走同一个 `client` |
| 登录后刷新就掉线 | Cookie 缺 `Path` / `Max-Age` | 检查 Cookie 属性 |
| 跨域带不上 Cookie | CORS 凭证与 `SameSite` 配置冲突 | 明确 origin + `credentials: true` |
| 密码校验很慢 | bcrypt 成本因子过高 | 按机器性能调整，通常 10–12 |
| JWT 泄露无法撤销 | 过期时间太长 | 缩短有效期 + refresh token |

## 9. 项目里怎么用

1. 建 `users`、`todos` 两张表，`todos.user_id` 外键；
2. 注册：校验 → 查重 → 哈希 → 入库；
3. 登录：查用户 → 校验哈希 → 建会话或签发 token；
4. 列表接口只返回当前用户的数据；
5. 给登录接口加限流，给错误响应去掉堆栈；
6. 写测试覆盖：重复注册、错误密码、越权访问。
