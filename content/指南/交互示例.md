## 它是怎么实现的

### 1. 示例组件

所有示例放在 `apps/vitepress/.vitepress/demos/` 下，按业务分子目录，一个示例一个 `.vue` 文件：

```text
.vitepress/demos/
├── counter/basic.vue
├── form/binding.vue
└── todo/basic.vue
```

示例就是普通 Vue 单文件组件，可以写 `<script setup>`、`<template>`、`<style scoped>`，也可以安装并使用任意前端依赖。为了保证构建阶段（SSR）不报错：

- 不要在 `setup` 顶层直接访问 `window`、`document`、`localStorage`；
- 需要浏览器环境时放进 `onMounted`；
- 异步请求放进事件回调或 `onMounted`。

### 2. 文档里引用

在任意 Markdown 中写一行即可，`src` 是相对于 `apps/vitepress/.vitepress/demos/` 的路径，**不写 `.vue` 后缀**：

```md
<DemoBlock src="counter/basic" title="响应式计数器" description="ref 保存状态，computed 派生 doubled。" />
```

`DemoBlock` 已在 `apps/vitepress/.vitepress/theme/index.ts` 中全局注册，不需要在 Markdown 里 `import`。

### 3. 源码为什么不会和示例脱节

组件在构建时通过 Vite 的 glob 拿到示例模块和原始文本：

```ts
const demos = import.meta.glob('../../demos/**/*.vue', { eager: true })
const sources = import.meta.glob('../../demos/**/*.vue', {
  eager: true,
  query: '?raw',
  import: 'default',
})
```

- 预览区渲染 `demos[src].default`；
- 「查看源码」展示 `sources[src]`，即同一个文件的原文；
- 点击时才动态 `import('shiki')` 做语法高亮，不拖慢首屏；
- 主题切换时自动换用 `github-light` / `github-dark`。

因此**不需要在 Markdown 里再抄一遍代码**，改示例文件就等于同时改了演示和源码。

## 新增一个示例

1. 在 `apps/vitepress/.vitepress/demos/` 下新建 `.vue` 文件，例如 `apps/vitepress/.vitepress/demos/chart/line.vue`；
2. 正常编写组件，确保 SSR 安全；
3. 在目标 Markdown 中加入：

   ```md
   <DemoBlock src="chart/line" title="折线图" description="用 SVG 画一条响应式折线。" />
   ```

4. 保存后开发服务器会热更新。若新增了依赖，先 `npm install` 再重启；
5. 提交前运行一次 `npm run build:vp`，确认构建阶段没有 `window is not defined` 之类的错误。

## 使用注意事项

| 场景 | 做法 |
| --- | --- |
| 示例需要 Element Plus 等库 | `npm i element-plus`，在示例组件内按需 `import`；样式同样在组件内引入 |
| 示例需要图片 / 静态资源 | 放到 `public/`，用 `/xxx.png` 引用；或与组件同目录并用相对路径 |
| 想默认展开源码 | 在 `DemoBlock.vue` 中把 `showCode` 初始值改为 `true` |
| 需要多个文件组成一个示例 | 把入口组件放 `xxx/index.vue`，`src` 写 `xxx`；其余文件正常 import |
| 构建报 `window is not defined` | 把浏览器 API 移入 `onMounted` 或事件回调 |

> 示例代码会原样展示，敏感信息（token、内网地址）不要写进 demo 文件。
