# 树选择（Tree）完整例子

> 树形数据的选择抽屉，提供两条路径：
> **方案一**用 `CompSelect` 直接开树模式（行级选择，几行配置搞定）；
> **方案二**自写选择抽屉，支持父子联动、只选末级、选中父级连带子级、前端过滤。
> 两者都基于 `CompDrawer` + `CompTableSearch` + `CompTable` 这套组合。

## 适用场景

- 主数据是**树结构**（部门/科室、分类、科目、区域…），需要在一个抽屉里挑若干节点。
- 数据量不大（几百到几千节点），接口一次性返回整棵树，不做分页。
- 可能需要：跨层级勾选、只允许选末级、选中父级时把子级一起带走。

## 方案一：CompSelect 树模式

`CompSelect` 的 `columns.table.attr` 会原样透传给 `CompTable`，所以树形属性直接写在这里：

```ts
/** 搜索项 + 表格列 */
const columns = {
  search: {
    attr: {},
    options: [{ prop: 'rollName', label: '科室名称' }],
  },
  table: {
    attr: {
      // 树形表格必须给 row-key；CompSelect 不会把顶层 keys 透传给 CompTable，所以要在这里再传一次
      keys: 'id',
      defaultExpandAll: true,
      treeProps: { children: 'children' },
    },
    options: [
      { prop: 'rollCode', label: '科室编码' },
      { prop: 'rollName', label: '科室名称' },
    ],
  },
}
```

```vue
<CompSelect
  v-model="show"
  title="归口科室"
  keys="id"
  :selected="selected"
  :max-length="0"
  :show-pagination="false"
  :query-key="() => queryKeys.rollDept.tree()"
  :api-fn="query => treeRollDept(query)"
  :columns="columns"
  @change="handleChange" />
```

适用条件与边界：

- **筛选交给后端**：`CompSelect` 把查询条件原样传给 `apiFn`，自己不做客户端过滤；接口不支持筛选就搜不出结果。
- **只做行级选择**：父子不联动、不能限定只选末级、选中父级不会连带子级。
- **关掉分页**：树接口一次返回整棵，`:show-pagination="false"`。

需要上面这些能力时，用方案二。

## 方案二：自定义树选择抽屉

### 完整代码

`components/RollDeptSelect/index.vue`：

```vue
<template>
  <comp-drawer
    v-model="show"
    :z-index="zIndex"
    :enable-scroll="false"
    title="归口科室"
    :tip="tip"
    @save="handleSave">
    <div class="app-container">
      <!-- 搜索条件 start -->
      <CompTableSearch
        :model="list.query"
        :loading="list.loading"
        @search="handleSearch"
        @reset="handleReset">
        <template #left>
          <CompCommonSearchItem
            v-model="list.query"
            :options="searchOptions" />
        </template>

        <template #right>
          <el-text class="mr10">{{ selectedRows.length }}{{ maxLength > 0 ? ` / ${maxLength}` : '' }}</el-text>
          <el-button-group>
            <el-button
              size="default"
              type="danger"
              @click="handleRemoveAll">
              清除所有
            </el-button>
            <el-button
              size="default"
              @click="handleSelectAll">
              全选
            </el-button>
          </el-button-group>
        </template>
      </CompTableSearch>
      <!-- 搜索条件 end -->

      <!-- 表格 start：树形表格用 keys 充当 row-key -->
      <CompTable
        v-model:list="list"
        keys="id"
        :selectable="false"
        :show-table-tool-bar="false"
        :min-width="120"
        default-expand-all>
        <CompTableColumn prop="action">
          <template #default="{ row }">
            <el-button
              v-if="canSelect(row)"
              :type="isCheckedRow(row) ? 'warning' : 'primary'"
              size="default"
              link
              :disabled="disabledRow(row)"
              @click="handleToggle(row)">
              {{ isCheckedRow(row) ? '取消' : '选择' }}
            </el-button>
          </template>
        </CompTableColumn>
      </CompTable>
      <!-- 表格 end -->
    </div>
  </comp-drawer>
</template>

<script lang="ts" setup>
  import type { CommonSearchItemOptions } from '@/components/CommonSearchItem/types'
  import type { TableColumn } from '@/components/CompTable/types'

  import { useAssign } from '@/hooks/useObject'
  import { useError } from '@/hooks/useTip'
  import { useDict } from '@/utils/dict'

  import { treeRollDept } from '@/api/masterBudget/budgetInfo'

  import CompCommonSearchItem from '@/components/CommonSearchItem/index.vue'
  import CompTable, { useCompTable } from '@/components/CompTable/index.vue'
  import CompDrawer from '@/components/Drawer/index.vue'
  import CompTableSearch from '@/components/TableSearch/index.vue'

  /** 查询条件（与 searchOptions 的 prop 一一对应） */
  interface RequestList {
    rollCode: string
    rollName: string
  }

  /** 树节点：按项目实际接口字段调整；用 type 而不是 interface，赋值给 Record 约束时更省事 */
  type ResponseList = {
    id: string
    rollCode?: string
    rollName?: string
    parentRollDeptName?: string
    budgetUnitName?: string
    isVirtual?: string
    dataSource?: string
    children?: ResponseList[]
  }

  interface Props {
    /** 描述标题 */
    tip?: string
    /** 指定弹窗层级 */
    zIndex?: number
    /** 已选择数据（可只传 id） */
    selected?: Partial<ResponseList>[]
    /** 最小选择数据 */
    minLength?: number
    /** 最大选择数据，0 表示不限制 */
    maxLength?: number
    /** 禁用选择行 */
    disabledRow?: (row: Partial<ResponseList>) => boolean
    /** 是否只允许选择末级节点 */
    leafOnly?: boolean
    /**
     * 选中的父级是否连带其所有子级一起返回
     * - true：父级选中时，其下所有子级也在 selected 中
     * - false：只返回最上层被选中的节点
     */
    includeChildren?: boolean
  }

  const props = withDefaults(defineProps<Props>(), {
    tip: undefined,
    zIndex: 1,
    selected: () => [],
    minLength: 1,
    maxLength: 500,
    disabledRow: () => false,
    leafOnly: false,
    includeChildren: false,
  })

  const emit = defineEmits<{ change: [rows: ResponseList[]] }>()
  const show = defineModel<boolean>({ default: false })

  /** ---------- 1. 数据：全量树 + 过滤后的展示树 ---------- */

  /** 客户端过滤：命中节点保留整棵子树，未命中但有命中后代的节点保留路径 */
  const filterTree = (nodes: ResponseList[], code: string, name: string): ResponseList[] => {
    const result: ResponseList[] = []
    nodes.forEach(node => {
      const children = filterTree(node.children ?? [], code, name)
      const isMatch = (!code || node.rollCode?.includes(code)) && (!name || node.rollName?.includes(name))
      if (isMatch || children.length) result.push({ ...node, children })
    })
    return result
  }

  /** 全量树：选择、联动、回显的真实数据源，不受过滤影响 */
  const fullTree = shallowRef<ResponseList[]>([])

  /**
   * 树接口不分页：
   * - enablePage = false，list.query 就是搜索条件
   * - 过滤在 queryFn 里做，返回的 data 供 CompTable 渲染
   * - queryKey 不包含查询条件（客户端过滤 + refetch 会强制执行 queryFn）；
   *   若改成后端过滤，记得把 query 带上
   */
  const { list, getList } = useListQuery<RequestList, ResponseList>(
    { rollCode: '', rollName: '' },
    () => queryKeys.rollDept.tree(),
    async query => {
      const res = await treeRollDept()
      const data = res.data ?? []
      fullTree.value = data
      const rollCode = (query.rollCode ?? '').trim()
      const rollName = (query.rollName ?? '').trim()
      return { ...res, data: filterTree(data, rollCode, rollName) }
    },
    { enablePage: false, enabled: computed(() => show.value) }
  )

  /** ---------- 2. 索引：id → 节点 / 父节点 ---------- */
  const treeIndex = computed(() => {
    const nodeMap = new Map<string, ResponseList>()
    const parentMap = new Map<string, ResponseList>()
    const walk = (nodes: ResponseList[], parent?: ResponseList) => {
      nodes.forEach(node => {
        const id = String(node.id)
        nodeMap.set(id, node)
        if (parent) parentMap.set(id, parent)
        walk(node.children ?? [], node)
      })
    }
    walk(fullTree.value)
    return { nodeMap, parentMap }
  })

  /** ---------- 3. 选择状态：checkedIds 是唯一真相 ---------- */
  const checkedIds = ref<Set<string>>(new Set())

  /** 节点及其全部后代 id */
  const subtreeIds = (node: ResponseList): string[] => [
    String(node.id),
    ...(node.children ?? []).flatMap(subtreeIds),
  ]

  /** 节点及其后代中「可选」的 id：禁用节点整棵子树跳过 */
  const selectableIds = (node: ResponseList): string[] =>
    props.disabledRow(node) ? [] : [String(node.id), ...(node.children ?? []).flatMap(selectableIds)]

  /** 末级节点：children 为空即末级（若后端用 isLeaf 标识且不下发空数组，改成判断 isLeaf） */
  const isLeafNode = (row: Partial<ResponseList>) => {
    const node = treeIndex.value.nodeMap.get(String(row.id)) ?? row
    return !node.children?.length
  }

  const isCheckedRow = (row: Partial<ResponseList>) => checkedIds.value.has(String(row.id))

  /** 行是否可选：仅末级模式下，非末级不展示操作按钮 */
  const canSelect = (row: Partial<ResponseList>) => !props.leafOnly || isLeafNode(row)

  /** 按树顺序输出勾选结果：includeChildren = false 时只返回最上层被选中的节点 */
  const collectSelectedRows = (set: Set<string>): ResponseList[] => {
    const { parentMap } = treeIndex.value
    const rows: ResponseList[] = []
    const walk = (nodes: ResponseList[]) => {
      nodes.forEach(node => {
        const id = String(node.id)
        if (set.has(id)) {
          const parent = parentMap.get(id)
          if (props.includeChildren || !parent || !set.has(String(parent.id))) rows.push(node)
        }
        walk(node.children ?? [])
      })
    }
    walk(fullTree.value)
    return rows
  }

  const selectedRows = computed(() => collectSelectedRows(checkedIds.value))

  /** 数量校验：以实际返回的 selected 为准（父级可能被联动勾选，不能只数 checkedIds） */
  const isOverLimit = (set: Set<string>) => props.maxLength > 0 && collectSelectedRows(set).length > props.maxLength

  /** 子级全选时同步父级选中状态；父级被禁用时只取消、不新增 */
  const syncParents = (set: Set<string>, node: ResponseList) => {
    let parent = treeIndex.value.parentMap.get(String(node.id))
    while (parent) {
      const children = (parent.children ?? []).filter(child => !props.disabledRow(child))
      const allChecked = children.length > 0 && children.every(child => set.has(String(child.id)))
      if (allChecked && !props.disabledRow(parent)) set.add(String(parent.id))
      else set.delete(String(parent.id))
      parent = treeIndex.value.parentMap.get(String(parent.id))
    }
  }

  /** 选择 / 取消单个节点（非仅末级时父子联动） */
  const handleToggle = (row: Partial<ResponseList>) => {
    const node = treeIndex.value.nodeMap.get(String(row.id))
    if (!node || props.disabledRow(node)) return
    const willCheck = !checkedIds.value.has(String(node.id))
    const next = new Set(checkedIds.value)
    if (props.leafOnly) {
      willCheck ? next.add(String(node.id)) : next.delete(String(node.id))
    } else {
      // 取消时用全量子树，避免禁用子节点残留在集合里
      const ids = willCheck ? selectableIds(node) : subtreeIds(node)
      ids.forEach(id => (willCheck ? next.add(id) : next.delete(id)))
      syncParents(next, node)
    }
    if (isOverLimit(next)) {
      useError('选择数量已超过限制')
      return
    }
    checkedIds.value = next
  }

  /** 清除所有 */
  const handleRemoveAll = () => {
    checkedIds.value = new Set()
  }

  /** 全选：禁用行整棵跳过；仅末级模式下只勾末级 */
  const handleSelectAll = () => {
    const next = new Set(checkedIds.value)
    const walk = (nodes: ResponseList[]) => {
      nodes.forEach(node => {
        if (props.disabledRow(node)) return walk(node.children ?? [])
        if (props.leafOnly && !isLeafNode(node)) return walk(node.children ?? [])
        selectableIds(node).forEach(id => next.add(id))
        walk(node.children ?? [])
      })
    }
    walk(fullTree.value)
    if (isOverLimit(next)) {
      useError('选择数量已超过限制')
      return
    }
    checkedIds.value = next
  }

  /** ---------- 4. 回显 ---------- */
  const isEchoed = ref(false)

  const echoChecked = () => {
    const { nodeMap } = treeIndex.value
    const next = new Set<string>()
    props.selected.forEach(item => {
      const node = nodeMap.get(String(item.id))
      if (!node) return
      if (props.leafOnly) {
        if (isLeafNode(node)) next.add(String(node.id))
        return
      }
      selectableIds(node).forEach(id => next.add(id))
      syncParents(next, node)
    })
    checkedIds.value = next
  }

  /**
   * 树数据是异步的，且接口只在打开时请求：
   * 所以同时监听「抽屉显隐 + 全量树」，两者都就绪才回显一次
   */
  watch(
    [() => show.value, fullTree],
    ([visible]) => {
      if (!visible) {
        isEchoed.value = false
        return
      }
      if (isEchoed.value || !fullTree.value.length) return
      echoChecked()
      isEchoed.value = true
    },
    { immediate: true }
  )

  /** ---------- 5. 表格列 ---------- */
  const { budget_dept_data_source } = useDict('budget_dept_data_source')

  const columns: TableColumn<ResponseList>[] = [
    { prop: 'rollCode', label: '科室编码' },
    { prop: 'rollName', label: '科室名称' },
    { prop: 'parentRollDeptName', label: '上级科室' },
    { prop: 'budgetUnitName', label: '预算单位' },
    { prop: 'isVirtual', label: '是否虚拟组织', format: { type: 'boolean' } },
    { prop: 'dataSource', label: '数据来源', format: { type: 'dict', formatStr: budget_dept_data_source } },
    // 操作列必须有列配置，单元格内容由下面的 <CompTableColumn prop="action"> 提供
    { prop: 'action', label: '操作', width: 100, fixed: 'right' },
  ]

  /** 注册列并拿到带行类型推导的 CompTableColumn（操作列内容写在模板里） */
  const { CompTableColumn } = useCompTable(columns)

  /** ---------- 6. 搜索 / 保存 ---------- */
  const searchOptions = computed<CommonSearchItemOptions<RequestList>[]>(() => [
    { prop: 'rollCode', label: '科室编码' },
    { prop: 'rollName', label: '科室名称' },
  ])

  const handleSearch = () => {
    getList()
  }

  const handleReset = () => {
    useAssign(list.query, { rollCode: '', rollName: '' })
    handleSearch()
  }

  const handleSave = () => {
    const rows = selectedRows.value
    if (rows.length < props.minLength) {
      useError(`至少需要选择${props.minLength}条数据`)
      return
    }
    if (props.maxLength > 0 && rows.length > props.maxLength) {
      useError(`最多只能选择${props.maxLength}条数据`)
      return
    }
    emit('change', rows)
    show.value = false
  }
</script>
```

## 关键实现拆解

### 全量树与展示树为什么是两份数据

| 数据 | 用途 | 特点 |
| --- | --- | --- |
| `fullTree`（`shallowRef`） | 选择、联动、回显、全选 | 接口原样数据，**永远完整** |
| `list.items` | 表格渲染 | `filterTree` 过滤后的结果，只影响"看得见什么" |

如果直接在过滤后的树上做联动，搜索之后父级可能不在列表里，`syncParents` 就找不到祖先；用 `fullTree` 建索引可以避免这类问题。`shallowRef` 是刻意的：树只整体替换，不做深层响应式，省下大树的代理开销。

### treeIndex：一次遍历建索引

```ts
const treeIndex = computed(() => {
  const nodeMap = new Map<string, ResponseList>()   // id → 节点
  const parentMap = new Map<string, ResponseList>() // id → 父节点
  ...
})
```

之后所有操作都是 O(1) 查表：`isLeafNode`、`handleToggle` 找节点、`syncParents` 向上找祖先、`echoChecked` 按 id 找节点。注意 id 统一 `String()`：后端有时给 number、有时给 string。

### checkedIds 作为唯一真相

- 只维护一个 `Set<string>`，UI 全部由 `isCheckedRow(row)` 派生，不做行级 `checked` 回写。
- `CompTable` 传 `:selectable="false"`，不使用勾选列——因为勾选列无法表达"父级被联动选中"和"操作列按钮在两态间切换"。
- `filterTree` 产出的新对象不影响选中：选中只看 id。

### 父子联动 syncParents

```ts
const handleToggle = (row) => {
  const node = treeIndex.value.nodeMap.get(String(row.id))
  const willCheck = !checkedIds.value.has(String(row.id))
  const next = new Set(checkedIds.value)

  const ids = willCheck ? selectableIds(node) : subtreeIds(node)
  ids.forEach(id => (willCheck ? next.add(id) : next.delete(id)))
  syncParents(next, node)   // 只向上修，不向下推
}
```

三条规则：

1. **选中/取消都作用于整棵子树**：点父级即全选其子孙，取消同理。
2. **只向上修正父级**：子级全部选中 → 父级选中；否则父级取消。祖先链逐层重算。
3. **禁用节点不参与**：`selectableIds` 跳过禁用子树，`syncParents` 只统计未禁用的子节点。

取消时用 `subtreeIds`（全量）而不是 `selectableIds`，避免历史上被选中的禁用子节点残留在集合里。

### leafOnly 与 includeChildren

| 组合 | 行为 |
| --- | --- |
| `leafOnly = true` | 非末级不显示操作按钮（`canSelect`），全选只勾末级，回显丢弃非末级 |
| `includeChildren = true` | 选中的父级连同所有子孙一起进 `selected` |
| `includeChildren = false`（默认） | 只返回最上层被选中的节点（父级已选中时，子级不再重复出现在结果里） |

`collectSelectedRows` 是唯一的结果出口，`selectedRows`、数量校验、保存都走它，所以"返回什么"只有一处逻辑。

### 回显为什么分成两步

```ts
watch([() => show.value, fullTree], ([visible]) => {
  if (!visible) { isEchoed.value = false; return }      // 关闭时复位
  if (isEchoed.value || !fullTree.value.length) return  // 只回显一次
  echoChecked()
  isEchoed.value = true
}, { immediate: true })
```

- 抽屉打开时树可能还没请求回来（`enabled` 依赖 `show`），所以必须等 `fullTree`。
- `isEchoed` 防止"回显 → 触发联动 → 再回显"的循环，也避免用户选完又被父组件的 `selected` 覆盖。
- 关闭时复位，下次打开重新以 `selected` 为准。

### 全选与数量校验

- 全选走 `fullTree` 而不是当前页/过滤结果：语义是"整棵树都选上"；如需"只选当前筛选结果"，把 `walk(fullTree.value)` 换成 `walk(list.items)`。
- `maxLength = 0` 表示不限；`isOverLimit` 用 `collectSelectedRows(set).length` 判断，因为勾选父级会联动子级，`checkedIds.size` 不等于最终返回条数。
- 超限直接拒绝并把错误提示出来，不像表格选择那样"挤掉末位"——树里挤掉哪条很难让用户预期。

## 两方案对比

| 能力 | 方案一 `CompSelect` 树模式 | 方案二 自定义树选择 |
| --- | --- | --- |
| 行级多选、搜索、回显 | ✅ 开箱即用 | ✅（要自己写） |
| 父子联动 | ❌ | ✅ |
| 只允许选末级 | ❌ | ✅ |
| 选中父级连带子级返回 | ❌ | ✅ |
| 前端过滤树（接口不支持筛选） | ❌ 只能后端筛 | ✅ |
| 数量上限 / 全选 | ✅ | ✅ |
| 代码量 | 一份 `columns` 配置 | 一个完整组件 |

结论：**行级选择直接用 `CompSelect`**；一旦需要联动、末级、前端过滤，就按方案二自写。

## 注意事项

1. **树形表格必须给 `row-key`**：这里用 `keys="id"`（`CompTable` 未传 `rowKey` 时回退 `keys`），否则展开、行更新都会异常。
2. **树接口不要分页**：`enablePage: false`，并且别在模板里放 `<pagination>`；`list.total` 为 0 也不影响渲染。
3. **过滤是客户端的**：查询条件不会发给后端（本例 `treeRollDept()` 无参调用）。若后端支持筛选，去掉 `filterTree` 并把 `query` 传给接口即可，`queryKey` 也要带上条件。
4. **`<CompTableColumn>` 必须配合 `useCompTable(columns)`**：列的真实配置（`label`/`width`/`fixed`/`format`）来自 `columns`，`CompTableColumn` 只提供单元格插槽；`columns` 里少了 `prop: 'action'` 这一项，操作列就不会出现。
5. **`<script setup>` 里不能出现 `export`**：示例里 `RequestList` / `ResponseList` 是局部声明的类型；需要给父组件复用时，把它们挪到同目录的 `types.ts` 再 `export` / import。
6. **id 类型统一转字符串**：`checkedIds` 存 `string`，比较前一律 `String()`，避免 `1` 与 `'1'` 不相等导致"选了但没选中"。
7. **`maxLength` 语义**：`0` = 不限；保存时 `minLength` 也参与校验，两者默认 `1` / `500`，按需覆盖。
8. **禁用行的两种拦截**：模板上 `:disabled` 只挡点击，`handleToggle` 里还有一次 `props.disabledRow(node)` 提前 return，双保险。

## 相对旧版例子的修改点

| 旧写法 | 现写法 | 原因 |
| --- | --- | --- |
| `<CompTable :columns="columns">` | 去掉 `:columns`，用 `useCompTable(columns)` | `CompTable` 已无 `columns` prop，列改由注入表提供 |
| `{ prop: 'action', slot: true }` + `#col-action` | `{ prop: 'action', ... }` + `<CompTableColumn prop="action">` | `TableColumn` 已无 `slot` 字段 |
| `h(ElButton, {...})` 渲染函数 + `ActionButton` 组件 | 模板里的 `<el-button>` | 列声明插槽自带行类型推导，不需要手写 render |
| `<script setup>` 内 `export type` | 局部声明的类型（或移入 `types.ts`） | `<script setup>` 不允许 ESM 导出 |
| `:list="list"` | `v-model:list="list"` | 与 `CompTable` 的双向绑定约定一致 |
| `isLeaf === YesOrNo.是 \|\| !children.length` | `!node.children?.length` | 纯结构判断，去掉对枚举的依赖（后端用 `isLeaf` 时按注释改） |
| 无禁用保护 | `handleToggle` 提前 return + `selectableIds` 跳过禁用子树 | 避免联动把禁用节点选进来 |
| `{{ selectedRows.length }} / {{ maxLength }}` | `maxLength = 0` 时只显示数量 | 与 `CompSelect` 的 `selectedText` 保持一致 |
