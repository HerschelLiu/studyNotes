# 表单缓存 `useFormCache`

> 表单草稿缓存与恢复（配合 useStorage）

解决「新增表单填到一半，误关抽屉 / 刷新页面 / 切走标签页，内容全没了」的场景：

- 新增态打开期间**自动**把表单内容写进 IndexedDB
- 再次打开抽屉（甚至刷新页面、重开浏览器）自动回填
- 保存成功后调用 `clearCache()` 清空缓存并重置表单
- 编辑态、预览态、抽屉关闭后**不监听、不序列化**，没有额外开销

只处理「新增态草稿」这一件事，不负责列表刷新、校验、提交，也不缓存编辑中的数据。

## 二、使用示例

### 示例 1：抽屉新增表单（最常用）

```vue
<template>
  <comp-drawer
    v-model="visible"
    title="新增项目"
    @save="handleSave">
    <el-form
      ref="ELForm"
      :model="form"
      :rules="rules"
      label-width="100px">
      <el-form-item
        label="项目名称"
        prop="name">
        <el-input
          v-model="form.name"
          placeholder="请输入项目名称"
          clearable />
      </el-form-item>

      <el-form-item
        label="项目金额"
        prop="amount">
        <el-input-number
          v-model="form.amount"
          :min="0"
          :precision="2"
          controls-position="right"
          style="width: 100%" />
      </el-form-item>

      <el-form-item
        label="备注"
        prop="remark">
        <el-input
          v-model="form.remark"
          type="textarea"
          :rows="3"
          placeholder="请输入备注" />
      </el-form-item>
    </el-form>
  </comp-drawer>
</template>

<script lang="ts" setup>
  import { addProject } from '@/api/project'

  import { useFormCache } from '@/hooks/useFormCache'
  import { useReactive } from '@/hooks/useObject'
  import { useRules } from '@/hooks/useRules'
  import { useSuccess } from '@/hooks/useTip'

  const ELForm = ref()
  const visible = ref(false)
  const loading = ref(false)

  /** useReactive 的第二项是重置函数，正好作为缓存的恢复基线 */
  const [form, resetForm] = useReactive({
    name: '',
    amount: undefined as number | undefined,
    remark: ''
  })

  const rules = useRules([{ key: 'name', label: '项目名称' }])

  /** 打开抽屉时恢复；关闭后保留；保存成功时清空 */
  const { clearCache } = useFormCache({
    key: 'project-add', // 同一页面内唯一即可，内部会拼上 route.path
    form,
    visible, // 抽屉显隐：关闭瞬间立即落盘
    reset: resetForm // 恢复前先复位，避免残留上一次的字段
  })

  const handleSave = async () => {
    await ELForm.value.validate()
    loading.value = true
    try {
      await addProject(form)
      useSuccess('新增成功')
      // 先清缓存再关抽屉：关闭时就没什么可写的了
      await clearCache()
      visible.value = false
    } finally {
      loading.value = false
    }
  }
</script>
```

弹窗（`el-dialog` / `comp-dialog`）用法完全一致，`visible` 传弹窗自己的显隐即可：

```ts
const { clearCache } = useFormCache({ key: 'project-add', form, visible: dialogVisible, reset: resetForm })
```

### 示例 2：页面级常驻表单

没有「关闭」这一刻，不传 `visible`：

```ts
const [form, resetForm] = useReactive({ title: '', content: '' })

const { clearCache } = useFormCache({
  key: 'notice-edit',
  form,
  reset: resetForm
})

const handleSubmit = async () => {
  await saveNotice(form)
  await clearCache()
}
```

组件挂载、IndexedDB 读取完成后立即恢复；输入靠 300ms 防抖落盘，另外在 `pagehide`、页面隐藏、组件销毁时兜底写入。

### 示例 3：新增 / 编辑共用一个抽屉

编辑态不应该读写草稿，用 `enabled` 关掉：

```ts
const visible = ref(false)
/** 当前编辑的记录；新增态为 undefined */
const detail = ref<ProjectDetail>()

const [form, resetForm] = useReactive({
  id: '',
  name: '',
  amount: undefined as number | undefined,
  remark: ''
})

const { clearCache } = useFormCache({
  key: 'project-form',
  form,
  visible,
  // 仅新增态参与缓存：编辑时既不恢复、也不监听、关闭也不写
  enabled: computed(() => !detail.value?.id),
  reset: resetForm
})

const handleAdd = () => {
  detail.value = undefined
  resetForm() // 没有缓存时 hook 不会调 reset，新增前要自己复位
  visible.value = true
}

const handleEdit = (row: ProjectDetail) => {
  detail.value = row
  resetForm()
  useAssign(form, row)
  visible.value = true
}

const handleSave = async () => {
  const isAdd = !detail.value?.id
  await ELForm.value.validate()
  const id = isAdd ? await addProject(form) : await updateProject(form)

  useSuccess(isAdd ? '新增成功' : '修改成功')
  // 编辑态调用也无害：本来就没写缓存，只会顺带重置
  await clearCache()
  if (isAdd) detail.value = { ...form, id }
  visible.value = false
}
```

这里有个顺带的好处：用户填了一半新增表单关掉、再去编辑某条记录，草稿**不会被编辑中的临时数据污染**，下次新增时还能接着填。

### 示例 4：缓存表单之外的额外状态（附件 uuid、Map、表格派生数据）

`form` 只放纯字段。附件列表、uuid、`Map`/`Set` 这类不能直接 JSON 化的状态，走 `extra`：

```ts
const attachmentUuid = ref('')
/** 已上传附件（服务端返回的结构，可 JSON 序列化） */
const attachments = ref<RequestAddAttachment[]>([])

const { clearCache } = useFormCache({
  key: 'contract-add',
  form,
  visible,
  reset: () => {
    resetForm()
    // reset 里要一并复位 extra 状态，否则清缓存后会残留
    attachmentUuid.value = ''
    attachments.value = []
  },
  extra: {
    /** 写入缓存时一起保存 */
    get: () => ({
      attachmentUuid: attachmentUuid.value,
      attachments: attachments.value
    }),
    /** 恢复时先于表单赋值执行 */
    set: data => {
      attachmentUuid.value = (data.attachmentUuid as string) || ''
      attachments.value = (data.attachments as RequestAddAttachment[]) || []
    }
  }
})
```

执行顺序是 `reset()` → `extra.set()` → `useAssign(form, payload.form)`，所以 `form` 里若有用到附件 uuid 的字段，回填时能拿到正确的值。

注意两点：

- `extra.get()` 的返回值必须是**可 JSON 序列化**的纯数据，`Map`/`Set`/`File` 直接返回会被序列化成 `{}`，请转成数组再存
- `Date` 会变成 ISO 字符串，恢复出来是字符串，需要时在 `extra.set` 里转回 `dayjs`/`Date`

### 示例 5：同一页面多个新增入口

`key` 只需要在同一页面内不重复，最终缓存键是 `minyi:form-cache:v1:${route.path}:${key}`：

```ts
// 收款单
useFormCache({ key: 'receipt-add', form, visible, reset: resetForm })
// 付款单
useFormCache({ key: 'payment-add', form, visible, reset: resetForm })
```

## 三、API

### options

| 参数       | 类型                                  | 必填 | 默认   | 说明                                                                                    |
| ---------- | ------------------------------------- | ---- | ------ | --------------------------------------------------------------------------------------- |
| `key`      | `MaybeRefOrGetter<string>`            | 是   | —      | 表单唯一 key：同一 `route.path` 内不重复即可，**只在 setup 时取一次值**                 |
| `form`     | `T extends object`                    | 是   | —      | `useReactive` 返回的表单对象（抽屉 / 弹窗 / 页面表单均可）                              |
| `visible`  | `MaybeRefOrGetter<boolean>`           | 否   | —      | 载体显隐。抽屉 / 弹窗传各自的 v-model；页面级表单不传，视为常驻可见（挂载即恢复）       |
| `enabled`  | `MaybeRefOrGetter<boolean>`           | 否   | `true` | 是否参与缓存。仅新增态可传 `computed(() => !data?.id)`                                  |
| `reset`    | `() => void`                          | 否   | —      | 恢复前重置基线；`clearCache` 时也会调用                                                 |
| `extra`    | `FormCacheExtra`                      | 否   | —      | 额外缓存状态，`get` 写入、`set` 恢复（先于表单赋值）                                    |
| `debounce` | `number`                              | 否   | `300`  | 变更后防抖写入间隔（ms）。大表单可调大到 500~1000                                       |

### 返回值

| 字段         | 类型                     | 说明                                         |
| ------------ | ------------------------ | -------------------------------------------- |
| `clearCache` | `() => Promise<void>`    | 保存成功后 `await` 调用：删除缓存 + 重置表单 |

### 缓存结构

```ts
interface FormCachePayload<T> {
  v?: number // 结构版本，用于升级时丢弃旧缓存
  form?: T
  extra?: Record<string, unknown>
}
```

## 四、源码

```ts
import type { MaybeRefOrGetter } from 'vue'

import { useIDBKeyval } from '@vueuse/integrations/useIDBKeyval'

import { useAssign } from '@/hooks/useObject'

/** 随表单一起缓存的额外状态（附件 uuid、表格派生态等，必须是可 JSON 序列化的纯数据） */
export interface FormCacheExtra {
  /** 写入缓存时返回需要一起保存的数据 */
  get: () => Record<string, unknown>
  /** 恢复时先于表单赋值执行，用于还原 Map、附件 uuid 等 */
  set: (data: Record<string, unknown>) => void
}

export interface UseFormCacheOptions<T extends object> {
  /** 表单唯一 key：同一页面（route.path）内不重复，组件生命周期内保持稳定 */
  key: MaybeRefOrGetter<string>
  /** useReactive 返回的表单对象，抽屉 / 弹窗 / 页面表单均可 */
  form: T
  /**
   * 载体显隐：
   * - 抽屉 / 弹窗：传各自的 v-model 显隐状态
   * - 页面级表单：不传，视为常驻可见（挂载即恢复）
   */
  visible?: MaybeRefOrGetter<boolean>
  /** 是否参与缓存，默认 true；仅新增态可传 `computed(() => !data?.id)` */
  enabled?: MaybeRefOrGetter<boolean>
  /** 恢复前重置基线；clearCache 时也会调用 */
  reset?: () => void
  /** 额外缓存状态 */
  extra?: FormCacheExtra
  /** 防抖写入间隔，默认 300ms */
  debounce?: number
}

export interface UseFormCacheResult {
  /** 保存成功后 await 调用：删除缓存 + 重置表单 */
  clearCache: () => Promise<void>
}

/** 缓存载荷：v 用于结构升级时丢弃旧缓存 */
interface FormCachePayload<T> {
  v?: number
  form?: T
  extra?: Record<string, unknown>
}

/**
 * 新增态表单缓存（抽屉 / 弹窗 / 页面表单通用）
 * - 打开时从 IndexedDB 恢复，关闭后保留，保存成功由 clearCache 清空
 * - 只在新增态打开期间做深度监听，编辑 / 预览 / 关闭不产生额外开销
 */
export function useFormCache<T extends object>(options: UseFormCacheOptions<T>): UseFormCacheResult {
  const { key, form, visible, enabled, reset, extra, debounce = 300 } = options

  const route = useRoute()
  // setup 阶段捕获：避免 keep-alive 页面切换路由后 key 串页
  const pagePath = route.path
  const cacheKey = `minyi:form-cache:v1:${pagePath}:${toValue(key)}`

  // VueUse 集成层：data 就是缓存里的字符串，赋值后自动写入 IndexedDB
  const {
    data: cacheValue,
    isFinished,
    set: setCacheValue
  } = useIDBKeyval<string | undefined>(cacheKey, undefined, { writeDefaults: false })

  const isVisible = computed(() => (visible === undefined ? true : toValue(visible)))
  const isEnabled = computed(() => (enabled === undefined ? true : toValue(enabled)))
  const isActive = computed(() => isVisible.value && isEnabled.value)

  let timer: ReturnType<typeof setTimeout> | undefined
  let stopFormWatch: (() => void) | undefined
  /** 抽屉 / 弹窗关闭后忽略页面 resetForm 触发的变更 */
  let isClosed = false
  /** clearCache 执行期间忽略 reset 触发的写入 */
  let isCleared = false
  /** 恢复期间忽略回填触发的写入 */
  let isRestoring = false
  /** 本次打开期间是否发生过变更 */
  let isDirty = false

  /** 删除缓存：useIDBKeyval 写入 undefined 时内部会执行 del(key) */
  const removeCache = async () => {
    await setCacheValue(undefined)
  }

  /** 立即写入：主线程只做序列化，落盘由 IndexedDB 异步完成 */
  const writeNow = () => {
    clearTimeout(timer)
    if (!isActive.value || isCleared) return
    try {
      const payload = JSON.stringify({
        v: 1,
        form,
        extra: extra ? extra.get() : {}
      })
      void setCacheValue(payload)
    } catch (error) {
      console.warn('[useFormCache] 缓存序列化失败，已跳过本次写入', error)
    }
    isDirty = false
  }

  /** 变更后防抖写入，避免每次输入都做一次全量序列化 */
  const scheduleWrite = () => {
    if (!isActive.value || isClosed || isCleared || isRestoring) return
    isDirty = true
    clearTimeout(timer)
    timer = setTimeout(writeNow, debounce)
  }

  // 只在新增态打开期间注册深度监听：编辑 / 预览 / 关闭时不遍历表单
  watch(
    isActive,
    active => {
      stopFormWatch?.()
      stopFormWatch = undefined
      if (active) stopFormWatch = watch(form, scheduleWrite, { deep: true })
    },
    { immediate: true }
  )

  /** 恢复缓存：先重置，再还原额外状态，最后回填表单 */
  const restore = () => {
    if (!isActive.value || !cacheValue.value) return

    let payload: FormCachePayload<T>
    try {
      payload = JSON.parse(cacheValue.value)
    } catch (error) {
      console.warn('[useFormCache] 缓存解析失败，已清除', error)
      void removeCache()
      return
    }

    // 版本不一致或载荷不完整：丢弃旧缓存
    if (payload.v !== 1 || !payload.form) {
      void removeCache()
      return
    }

    isRestoring = true
    reset?.()
    extra?.set(payload.extra ?? {})
    useAssign(form, payload.form)
    isDirty = false
    // 等回填触发的深度监听执行完再结束恢复态
    void nextTick(() => {
      isRestoring = false
    })
  }

  // 打开（新增态）且 IndexedDB 读取完成后恢复
  watch(
    [isActive, isFinished],
    ([active, finished]) => {
      if (!active || !finished) return
      isClosed = false
      isDirty = false
      restore()
    },
    { flush: 'post', immediate: true }
  )

  // 抽屉 / 弹窗关闭：先把最新内容写入缓存，再让页面 resetForm；页面级表单不注册
  if (visible !== undefined) {
    watch(
      isVisible,
      visibleNow => {
        if (visibleNow) return
        if (isDirty) writeNow()
        isClosed = true
      },
      { flush: 'sync' }
    )
  }

  /** 关 tab / 页面隐藏 / 路由离开：尽力立即落盘 */
  const flushOnHide = () => {
    if (isActive.value && isDirty) writeNow()
  }

  const handleVisibilityChange = () => {
    if (document.visibilityState === 'hidden') flushOnHide()
  }

  window.addEventListener('pagehide', flushOnHide)
  document.addEventListener('visibilitychange', handleVisibilityChange)
  onScopeDispose(() => {
    flushOnHide()
    window.removeEventListener('pagehide', flushOnHide)
    document.removeEventListener('visibilitychange', handleVisibilityChange)
    stopFormWatch?.()
  })

  /** 保存成功后调用：删除缓存 + 重置表单，并吞掉 reset 产生的写入 */
  const clearCache = async () => {
    clearTimeout(timer)
    isCleared = true
    await removeCache()
    reset?.()
    await nextTick()
    isCleared = false
    isDirty = false
  }

  return { clearCache }
}
```

## 五、实现要点

### 1. 只在「新增态 + 可见」期间监听表单

`isActive = isVisible && isEnabled`，深度监听在 `isActive` 变化时挂载 / 卸载：

| isActive | 深度监听 | 能恢复 | 关闭时落盘 |
| -------- | -------- | ------ | ---------- |
| `true`   | 有       | 能     | 能         |
| `false`  | 无       | 不能   | 不能       |

所以编辑态、预览态、抽屉关闭后都不会再遍历表单，页面里几十个表单同时存在也没有额外开销。

### 2. 三个标志位负责「写入时机」的边界

| 标志位       | 作用                                                             |
| ------------ | ---------------------------------------------------------------- |
| `isRestoring` | 回填期间忽略深度监听的回调，避免「刚恢复就写回」的无效写入       |
| `isClosed`   | 抽屉关闭后忽略页面 `resetForm()` 引发的变更，避免关闭后又被写脏  |
| `isCleared`  | `clearCache` 期间忽略 `reset()` 触发的写入，避免「清完又写一份空表单」 |

### 3. 落盘时机

- 输入过程中：防抖 300ms（`debounce` 可调）
- 抽屉 / 弹窗关闭：`flush: 'sync'` 立即写入，保证紧接着的 `resetForm()` 不会把缓存覆盖成空表单
- 关闭标签页、切走页面、组件销毁：`pagehide` / `visibilitychange` / `onScopeDispose` 兜底写入
- 保存成功：`clearCache()` 删除缓存 + 重置表单

### 4. 版本号让结构升级可以「安全作废」旧缓存

缓存键里有 `v1`，载荷里也有 `payload.v !== 1` 校验。表单字段改名、增删或含义变化时，把这两处的 `v1` 一起改成 `v2`，旧缓存会被自动识别并删除，不会把旧结构的数据回填进新表单。

### 5. 回填用 `useAssign`，遵循「以 form 字段为准」

`useAssign(form, payload.form)` 只会写回 `form` 里**已声明**的字段，缓存里多出来的字段会被忽略。好处是新增了字段也不会被旧缓存写坏，坏处是字段没在 `useReactive` 初始值里声明就永远不会被恢复。

## 六、注意事项

1. **`key` 只在 setup 时求值一次**
   传 ref / getter 只是为了读当时的值，运行中修改它不会切换缓存。需要「多份草稿」请用多个固定 key，或让组件重新创建（如 `:key` 重建）。

2. **缓存键绑定 `route.path`，且是 setup 时捕获的**
   这是为了 keep-alive 页面切换路由后不串页。反过来说：如果同一个页面组件既要服务 `/a` 又要服务 `/b` 且共用同一个实例，缓存会落在首次进入的那个路径下。

3. **只缓存纯 JSON 数据**
   `form` 里不要放 `Map`、`Set`、`File`、`Blob`、类实例、循环引用。`undefined` 字段序列化后会丢，恢复时不会写回（不会覆盖 `form` 里的默认值）。`Date` 会变成字符串。

4. **没有缓存时不会调用 `reset`**
   `reset` 只在「有缓存要恢复」和「`clearCache`」时执行。新增前需要自己复位，建议在 `handleAdd` 里显式 `resetForm()`。

5. **敏感信息不要进缓存**
   数据明文存在浏览器 IndexedDB 里，同源脚本可读。证件号、密码、token 这类字段请在提交前从 `form` 剥离，或干脆不用这个 hook。

6. **多标签页是「后写覆盖」**
   没有版本冲突检测。两个标签页同时填同一份表单，后关闭的那个覆盖前面的。

7. **IndexedDB 不可用时自动降级**
   无痕模式或部分内嵌 webview 读取失败时，`isFinished` 不会变成 `true`，表现就是「不缓存、不恢复」，但不影响表单正常填写和提交。`JSON.stringify` 失败也会只 `console.warn` 跳过本次写入，不打断用户操作。

8. **取消关闭时缓存会保留**
   这是「防误关」的核心。如果某个入口希望取消即丢弃，取消时也调用一次 `clearCache()` 即可（顺带重置表单）。

9. **大表单适当调大 `debounce`**
   每次写入是整表全量序列化，字段多、含长文本时把 `debounce` 调到 500~1000，减少主线程占用；`writeNow` 只做序列化，落盘是 IndexedDB 异步完成。

## 七、常见问题

**Q：为什么保存成功后既要 `clearCache()` 又要 `visible = false`？**
A：`clearCache()` 负责「删缓存 + 复位表单」，`visible = false` 负责关闭载体。顺序建议先 `await clearCache()` 再关闭，这样关闭瞬间 `isDirty` 已是 `false`，不会再多写一次已保存的数据。

**Q：编辑态需要缓存吗？**
A：不需要。编辑态的草稿意义不大且容易和「未保存的脏数据」混淆，用 `enabled: computed(() => !data?.id)` 明确关掉即可。

**Q：能在 `el-dialog` 里用吗？**
A：可以，`visible` 传 `dialogVisible` 或 `computed(() => dialogVisible.value)` 都行；`destroy-on-close` 也无需特殊处理，因为表单数据在父组件的 `useReactive` 里，不在弹窗内部。

**Q：用户清除了站点数据 / 换了浏览器怎么办？**
A：缓存就是没了，等同于首次打开，不报错、不影响提交。
